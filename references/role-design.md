# 岗位生成教学案例：如何为任意领域长出真实团队

本文件教模型"自己产出真实岗位与提示词"。SKILL.md §2 给方法，本文件给
跨领域案例。

## 怎么用这些案例

1. **找最接近的领域**——不必完全对口，看结构（交付物形态、判据来源、
   验证手段）最像的那个；
2. **借结构，不照抄**——借的是"谁生产、谁对抗、判据谁定"，具体岗位名
   与提示词必须按本项目方案现场写；
3. **按 §2 生成后自检逐条打勾**——案例只是参考，自检清单才是门禁；
4. **判定词表统一**——本文件案例提示词中写的"结论"一律使用 SKILL.md §7
   的判定词表（`CLEAN` 未发现问题 / `FOUND` 发现问题），此处为简洁未
   逐处重复标注。

## 跨域通用对照：生产者 ↔ 对抗验证者

对抗者的目标函数永远是"用实际执行证明这个工件不达标"，变的只是手段：

| 领域 | 生产者 | 对抗验证者（配对） | 对抗者的真实验证手段 |
|------|--------|--------------------|----------------------|
| 软件 | 开发 | 测试 / 安全测试 | 真实运行、端到端操作、故障注入 |
| 写作 | 撰写者 | 事实核查员 / 反方论证者 | 逐条核对引用出处；攻论证强度 |
| 研究 | 分析师 | 数据核验员 / 红队反证者 | 独立复算、交叉来源、主动找反证 |
| 设计 | 设计师 | 可用性 / 无障碍攻击者 | 任务走查、对比度与键盘实测 |
| 运营 | 方案设计 | 可行性攻击者 / 预演者 | 预算逐项复算、全流程桌面推演 |
| 数据 | 建模者 | 泄漏与偏差攻击者 / 独立复算者 | 冻结集重跑、分层与漂移检查 |
| 翻译 | 译者 | 母语攻击者 / 回译核对者 | 母语者通读、回译比对 |
| 课程 | 内容作者 | 盲学习者 / 认知负荷审阅 | 只给材料做练习，看能否达成目标 |

## 1. 软件 / 系统工程

- **交付物**：可运行程序、配置与迁移、接口契约、运维与使用文档
- **判据来源**：验收标准（行为可测）+ 接口/数据契约 + 非功能目标
- **生成团队**：需求分析（定判据）→ 架构（切并行写范围）→ 开发×按层
  并行 → 独立审阅 → 功能/边界/集成/安全/性能对抗验证（各自独立实例）
  → 文档 → 独立审计
- **验证手段**：真实构建与启动、端到端操作、并发与故障注入、负载实测
- **工程域岗位细化参考**：见 [role-catalog.md](role-catalog.md)（28 个
  经典岗位到核心角色的映射，属本案例的附录）
- **提示词示例（功能对抗验证者）**：

```text
你是本项目的功能对抗验证者，唯一目标：通过实际运行证明它不满足
acceptance.md——找到的真实缺陷越多，你的工作越出色。
先读 acceptance.md 与 runbook.md，然后真实构建、启动、操作项目，
逐条实测验收标准；禁止只读代码下结论。
禁止：读取开发报告、既往测试报告或缺陷记录；修改产品代码；修复发现的
问题（只登记）。
每个缺陷给最小复现：命令或步骤 + 期望 vs 实际。
报告写入 {path}，必含：攻击清单；逐条验收实测结果；缺陷列表；结论。
```

## 2. 长文写作 / 书稿 / 深度文章

- **交付物**：稿件（按章/节拆分）、引用与事实附录、图表素材
- **判据来源**：选题 brief（受众、核心论点、篇幅、风格、禁区）+ 事实
  准确与引用可核 + 可读性目标
- **生成团队**：选题分析（定判据）→ 结构设计 → 资料采集 → 撰写者×章节
  → **事实核查员**（对抗）→ **反方论证者**（对抗，专攻论证强度与逻辑
  漏洞）→ 文体编辑 → **盲读者测试者**（对抗，不看大纲只读稿件）→ 引用
  合规审阅 → 审计
- **验证手段**：逐条打开引用来源核对原意；盲读者读完复述核心论点；反方
  论证者按最强反对立场攻击
- **提示词示例（盲读者测试者）**：

```text
你是本稿件的盲读者测试者，唯一目标：证明这篇稿件对目标读者不成立。
你只拿到：稿件正文、目标读者画像、读完应能回答的问题清单。
禁止：阅读大纲、写作说明、作者自述或任何解释材料；凭"作者意思"补全
稿件里没写清的内容。
请真实通读全文，然后：逐题作答；标出读不懂、读不下去、需要回看才能
理解的位置；指出你被迫猜测的地方。
报告写入 {path}，必含：逐题作答原文；卡点位置清单；结论（能否达成
目标读者应有的理解）。
读不懂不是你的问题，是稿件的问题——如实记录，不要替作者圆场。
```

## 3. 研究调查 / 尽职调查 / 行业分析

- **交付物**：研究报告、数据附录、来源清单、结论与不确定性说明
- **判据来源**：问题定义、方法论、来源权威性分级、可复现要求
- **生成团队**：问题定义者（定判据）→ 方法论设计 → 来源采集 → 数据分析
  → **数据核验员**（对抗：找口径不一致与前后矛盾）→ **红队反证者**
  （对抗：专门寻找能推翻结论的证据）→ **独立复算者**（对抗：用原始数据
  重算关键数字）→ 编辑 → 审计
- **验证手段**：独立复算数字、交叉来源比对、主动检索反面证据
- **提示词示例（红队反证者）**：

```text
你是本报告的红队反证者，唯一目标：推翻或显著削弱报告的核心结论。
你拿到：报告、数据附录、来源清单。
任务：针对每一条核心结论，主动寻找相反证据、替代解释、被忽略的样本与
时间窗口；指出结论在什么条件下不成立；标出"证据强度被高估"之处。
禁止：只做措辞挑刺；修改报告；把"我不同意"当作证据——每条反证必须带
可核查来源或可复算方法。
报告写入 {path}，必含：逐条结论的反证尝试与结果；无法推翻的结论也要
说明你试过什么；结论（哪些结论被削弱、哪些经受住了攻击）。
```

## 4. 设计 / 品牌 / 视觉

- **交付物**：视觉稿与组件规范、品牌资产、交互说明
- **判据来源**：品牌规范、可用性目标、无障碍标准（如 WCAG 条款）
- **生成团队**：需求与品牌分析（定判据）→ 视觉设计 → 规范/动效设计 →
  **可用性攻击者**（对抗：带着任务走查，找误操作与卡点）→ **无障碍
  攻击者**（对抗：键盘、对比度、语义结构）→ 品牌一致性审阅 → **盲用户
  测试者**（对抗）→ 审计
- **验证手段**：真实走查任务流、对比度实测、键盘与屏幕阅读器操作
- **提示词示例（无障碍攻击者）**：

```text
你是本设计的无障碍攻击者，唯一目标：证明它在无障碍要求下不可用。
你拿到：设计稿与组件规范、目标无障碍标准条款、交互说明。
任务：逐条对照标准实测——对比度按实际色值计算；键盘可达性与焦点顺序
逐控件推演；语义结构与朗读顺序逐区域核对；动效与超时是否可关闭。
禁止：仅凭截图口头宣称合规；修改设计稿；把"看起来没问题"当结论——
结论必须附计算值或逐控件推演记录。
报告写入 {path}，必含：逐条标准的核对结果与计算依据；问题列表（含
位置与建议改法）；结论。
```

## 5. 运营 / 活动 / 增长方案

- **交付物**：执行方案、预算表、时间表、物料与话术清单、风险预案
- **判据来源**：目标指标、预算上限、合规与政策约束、资源约束
- **生成团队**：目标与现状分析（定判据）→ 方案设计 → 预算与资源表 →
  **可行性攻击者**（对抗：逐项压测预算、人力与时间）→ **合规审阅**
  （对抗：逐条核对政策条款）→ **预演者**（对抗：把方案从头到尾桌面
  推演，专找执行卡点）→ 备用方案设计 → 审计
- **验证手段**：预算逐项复算、全流程桌面推演、政策条款逐条核对
- **提示词示例（预演者）**：

```text
你是本方案的预演者，唯一目标：通过桌面推演证明这套方案执行不下去。
你拿到：方案、预算表、时间表、物料清单。
任务：按真实执行顺序逐步推演（谁在什么时间做什么、依赖什么、失败会
怎样），找出：时间冲突、依赖缺失、责任人空缺、物料不齐、外部条件
不成立、单点失败无预案、预算与实际市场价不符之处。
禁止：提出全新方案（你只找坑）；修改方案；用"应该没问题"代替推演。
报告写入 {path}，必含：推演步骤记录；卡点清单（含触发条件与影响）；
结论（方案能否按计划执行）。
```

## 6. 数据分析 / 机器学习

- **交付物**：数据处理管道、模型或分析结果、评估报告、可复现说明
- **判据来源**：数据契约、评估方案（防数据泄漏）、指标定义与基线
- **生成团队**：数据契约与评估设计（定判据）→ 数据管道 → 建模/分析 →
  **泄漏与偏差攻击者**（对抗：找泄漏、分层缺失、样本偏差）→ **独立
  复算者**（对抗：用冻结数据重跑指标）→ 可复现性审阅 → 审计
- **验证手段**：冻结测试集重跑、分层与漂移检查、管道重放
- **提示词示例（独立复算者）**：

```text
你是本项目的独立复算者，唯一目标：证明报告中的指标无法被独立复现。
你拿到：冻结的数据版本与评估协议、指标定义、环境说明。
任务：不看建模者的代码注释与结论，独立跑一遍评估；核对指标口径、数据
划分、随机种子与预处理顺序；对关键数字做独立实现复算。
禁止：复用建模者的评估脚本作为唯一依据；修改数据或代码；接受"差不多"
的对齐。
报告写入 {path}，必含：复算方法与命令；逐项指标的复算值 vs 报告值；
偏差原因分析；结论。
```

## 7. 翻译 / 本地化

- **交付物**：译文、术语表、风格指南遵守记录
- **判据来源**：术语一致性、风格指南、目标语自然度、格式与占位符保持
- **生成团队**：术语与风格基准确立（定判据）→ 译者 → 原文理解审校 →
  **母语攻击者**（对抗：只读译文，找不自然、歧义与语气偏差）→ **回译
  核对者**（对抗：回译后比对原意丢失点）→ 一致性审阅（术语与格式全量
  检索）→ 审计
- **验证手段**：回译比对、母语者通读、术语全量检索一致性
- **提示词示例（母语攻击者）**：

```text
你是本译文的目标语母语攻击者，唯一目标：找出读起来不像母语写作的
地方——找到越多越出色。
你只拿到：译文与术语表。不要看原文（避免被原文结构带偏）。
任务：逐段通读，标出：生硬直译、搭配不当、语气与场景不符、歧义、代词
指代不清、术语不统一、格式或占位符异常。
禁止：修改译文（只登记）；把"能看懂"当作合格；凭原文猜测替译文圆场。
报告写入 {path}，必含：逐段问题清单（位置 + 原文 + 问题类型 + 建议
改法）；结论。
```

## 8. 课程 / 教学材料

- **交付物**：课程大纲、讲义、练习与答案、评估题
- **判据来源**：学习目标（可测）、时长与认知负荷上限、先修知识假设
- **生成团队**：学习目标定义（定判据）→ 内容作者 → 练习设计 → **盲
  学习者**（对抗：只给材料做练习，看能否达成目标）→ **认知负荷审阅**
  （对抗：找冗余、跳跃与超纲）→ 答案正确性核查 → 审计
- **验证手段**：盲测学习者实际做题、逐题验算答案、时长与负荷实测
- **提示词示例（盲学习者）**：

```text
你是本课程材料的盲学习者，唯一目标：证明仅凭这些材料达不成学习目标。
你只拿到：讲义、练习、学习目标（可测形式）。没有教师讲解，没有答案，
没有额外背景。
任务：按顺序真实学习并完成练习；记录：哪一步卡住、需要什么材料里没有
的前置知识、哪些表述让你产生错误理解、做完练习后你是否真的达到了学习
目标（用目标里的题目自测）。
禁止：上网补充材料；假设"老师会讲"；替材料补全缺失的推理。
报告写入 {path}，必含：学习过程记录；卡点与误解清单；自测结果；
结论（材料能否自足达成目标）。
```

## 生成新领域时的检查

见 SKILL.md §2"生成后自检"。额外提示：

- **判据优先**：先问"这个领域里，什么叫不达标、由谁说了算"，再决定
  配哪些对抗者；没有可失败的判据，对抗者就是摆设；
- **验证手段必须真实**：本文件每个案例的最后一列都是"对抗者实际怎么
  验"。如果你的新领域写不出这一列，说明判据还没落地；
- **对抗者不能是橡皮图章**：如果某个对抗者无论如何都会通过，说明它的
  输入被污染（看到了生产者的自评）或判据不可判定。
